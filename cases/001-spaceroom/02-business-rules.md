# STEP 1 — 요구사항에서 업무 규칙 추출

- 날짜: 2026-11-23
- 평가: **통과**

## 1. 최초 답변 — 원문

### ① 도메인 용어

- 회의실 : 공유 오피스내 존재하고 입주사 직원들이 사용하기 위해 서비스에서 예약하는 주체
- 직원 : 공유 오피스 내 입주한 회사(입주사)에서 근무하는 직원
- 관리자 : 공유 오피스의 회의실을 관리하는 사람
- 예약 : 직원이 특정 시간대에 관리자가 등록한 회의실을 점유할 것이라고 공개하는 행위
- 사용 시작 시간 : 회의실 예약시에 필요한 정보로, 해당 회의실 사용을 시작하는 시간
- 사용 종료 시간 : 회의실 예약시에 필요한 정보로, 해당 회의실 사용을 종료하는 시간
- 예약 변경 : 직원이 미리 등록한 예약의 시간(사용 시작 시간, 사용 종료 시간)을 변경하는 행위
- 예약 취소 : 직원이 미리 등록한 예약을 삭제하는 행위
- 예약 조회 : 직원이 등록한 예약의 정보를 확인하는 행위
- 이름 : 회의실의 이름
- 수용 인원 : 회의실이 수용 가능한 인원 수
- 위치 : 회의실의 위치
- 이용 가능한 시설 정보 : 회의실 외 공유 오피스에서 이용 가능한 시설 정보
- 사용 제한 : 관리자가 모종의 이유로 특정 시간대에 회의실 사용을 금지하는 행위
- 중복 예약 : 특정 시간대에 최소 2명의 직원이 각각 입력한 사용 시작 시간, 사용 종료 시간이 겹치는 예약

### ② 명시적 비즈니스 규칙

- 회의실은 이름, 수용 인원, 위치, 이용 가능한 시설 정보를 가진다.
- 예약은 회의실, 날짜, 시간대, 입주사 직원을 가진다.
- 예약 시 직원이 시간을 선택할 때 30분 단위로 선택 하도록 해야한다.

### ③ 암묵적 비즈니스 규칙

- 입주사의 직원단위가 아니라 입주사 단위로 서비스를 이용한다.
- 각 예약별로 예약 취소 가능 시간을 가지고 있어야 한다.

### ④ 추가 확인할 정책

- 회의실 삭제 시, 미래 예약이 존재하는 경우의 정책
- 회의실 사용 제한 시간에 예약이 존재하는 경우의 정책

## 2. 최초 답변에 대한 멘토 피드백

| 주제 | 피드백 |
|---|---|
| 회의실 | 예약 주체가 아니라 **예약 대상** |
| 예약 | 단순 공개 행위가 아닌 업무적으로 확보된 사용 일정의 의미를 검토 |
| 예약 변경 | 시간뿐 아니라 회의실 변경도 허용됨 |
| 예약 취소 | 취소를 데이터 삭제로 정의할 근거 없음 |
| 시설 정보 | 공유 오피스 전체가 아니라 해당 회의실의 시설 |
| 중복 예약 | 서로 다른 직원이어야만 중복되는 것은 아님 |
| 데이터와 규칙 | 이름·수용 인원 등의 데이터 요구사항과 행동 허용·금지 규칙 분리 |
| 시작 시간 | 기획서에 30분 단위로 확정된 것은 **시작 시각** |
| 암묵적 규칙 | 입주사 단위 사용은 근거 부족, 취소 가능 시각 저장은 구현 가정 |
| 정책 발견 | 기획서에 명시된 미결정 사항 외의 숨은 정책도 찾아야 함 |

**놓친 명시적 규칙:** 30분~4시간 예약, 시간 중복 금지, 시작 1시간 전 취소, 변경 실패 시 기존 예약 유지, 사용 제한 중 신규 예약 금지.

## 3. 추가 검증 ①

**질문 A:** A가 10:00~12:00 예약. B가 같은 방 11:00~13:00 요청. 어떻게 처리할까?

**사용자 답변 (원문)**
> 동일 회의실에 대해 이용 시간이 겹치는 예약은 허용하지 않는다.

**멘토 피드백:** 정확. 일부 시간만 겹쳐도 충돌하며 뒤의 요청은 거절.

**질문 B:** 예약 사용 시작 이후 변경 가능 여부를 어떻게 확인할까?

**사용자 답변 (원문)**
> 사용 시작 시간이 지났는데 예약 변경이 가능한가?

**멘토 피드백:** 정확. 변경 가능 시점은 미정책이며 확인이 필요함.

## 4. 추가 검증 ②

현재 14:30, 기존 예약 15:00~16:00.
- A 행동: 취소
- B 행동: 17:00~18:00으로 변경

**사용자 답변 (원문)**
> 예약 취소: 거절
> 예약 변경: 미결정
> 판단 근거: 예약 취소는 직원의 회의실 사용 취소 의도가 명확하지만 변경은 직원이 다른 시간대에 사용하려고 하는 의도가 있기 때문에 정책 확인이 필요하다.

**멘토 피드백:** 결과는 맞지만 이유는 수정 필요. 취소는 시작 1시간 전 제한 위반이므로 거절하는 것. 변경은 시간 제한이 명시되지 않았음. 변경으로 취소 제한을 우회하는 경우도 미결정 정책으로 검토해야 함.
